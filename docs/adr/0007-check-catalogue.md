# 0007: Check catalogue: exact token identity, no inline suppressions, contract tests

- Status: accepted
- Date: 2026-11-25
- Tracker: T-0022

## Context and problem statement

The brief lists eight blocking checks and asks for a rule sheet for each: its scope, the values it allows, how it's exempted, and a passing and a failing fixture. Writing the [check catalogue](../spec/check-catalogue.md) raised eight choices that shape what the checks can catch and how far the agent can work around them.

## Considered options

1. **Token conformance:** compare computed values with token values; read the authored declarations and follow them to the token; both.
2. **Inline suppressions** (`eslint-disable`, `@ts-expect-error`): forbidden; allowed with a reason.
3. **Tests:** contract tests generated by the harness plus behaviour tests by the agent; the agent's tests only.
4. **Visual diff:** linux/amd64 with a strict comparison; linux/amd64 with a small tolerance; baselines per architecture.
5. **Target size:** WCAG 2.5.8 with its spacing exception; a strict 24 by 24 px minimum.
6. **axe's undecided results:** reported without failing; failing.
7. **Fixtures in M0:** static HTML for the rendered checks now, the framework-specific ones in M1; all described now, all files in M1.
8. **The spec's accessibility fields:** checked against the rendered component; axe's rules only.

## Decision outcome

The maintainer chose:

1. **Authored declarations.** The tokens check reads the winning CSS declaration of each token-bound property through the Chromium DevTools protocol and follows its custom properties to the token. It knows which token was used, so a raw token or the wrong token fails even when the values coincide. It ties the check to Chromium, which the verifier uses anyway.
2. **Forbidden.** Lint fails any inline suppression in a component's files; only an exemption in the spec waives a check.
3. **Harness and agent.** The harness generates contract tests from the approved API (the component's API matches it, every story renders without console errors), which the agent can't edit; the agent writes behaviour tests.
4. **linux/amd64, strict.** Captures are made only on linux/amd64, with no differing pixel allowed at a colour threshold of 0.1. M1 measures whether this holds.
5. **WCAG 2.5.8,** including its spacing and inline exceptions.
6. **Reported, not failing.** Undecided results appear in the report and the pull request summary.
7. **HTML now.** The rendered checks' fixtures are framework-neutral HTML pages in this repository; the build, lint, test and package fixtures arrive with the Vue adapter in M1.
8. **Checked.** The `a11y` check compares each element's role, accessible name and listed ARIA attributes with the spec.

The catalogue also sets these defaults: every check that can run does; warnings are errors; a rule of ESLint's or Stylelint's own can't be exempted for one component; an exemption for a source check applies to the whole component; an element that scrolls needs an exemption, so intended scrolling is visible to the reviewer.

### Consequences

- The adapter boundary (T-0031) includes reading a component's API for the contract tests, and the commands for the source checks.
- The token set (T-0033) says which tokens are role tokens and how custom properties are named; the fixtures use provisional rules until then. The story frame's base styles come from tokens.
- Apple Silicon laptops run the verifier emulated, which is slower than native.
- The Dialog example's exemption for its scrolling body names `layout`/`scroll`.
