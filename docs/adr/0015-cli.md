# 0015: CLI: explicit decision commands, feedback by command, JSON output everywhere

- Status: accepted
- Date: 2026-11-25
- Tracker: T-0030

## Context and problem statement

The CLI is the adopter's interface. The brief names its main commands (`init`, `spec new`, `spec check`, `propose`, `generate`, `report`, `verify`), and the earlier M0 documents add the baseline command, a drift check for generated files, listing and pruning run records, an image upgrade, and the maintainer's measurement and calibration. Two of the three decision points belong to the developer, and the CLI decides how they are made. The [CLI reference](../spec/cli.md) settles every command.

## Considered options

1. **API approval and accepting a result:** explicit `fazon approve` and `fazon accept` commands; y/n prompts at the end of `propose` and `generate`.
2. **Review feedback:** a `fazon feedback` command; a prompt in the terminal after `fazon report`.
3. **Machine-readable output:** `--json` on every command, with fixed exit codes; `--json` only where it seems useful.

## Decision outcome

The maintainer chose:

1. **Explicit commands.** `approve` records the API's hash; `accept` marks the run accepted and writes the provenance. Nothing waits on a prompt, and both are scriptable.
2. **`fazon feedback <component> -m <text>`,** which starts a linked feedback run; the static report shows the command to copy.
3. **`--json` everywhere,** printing one document in a common envelope (command, status, exit code, messages with hints, result), with exit codes 0, 1, 2, 3 and 130.

The reference also:

- has `propose` write the proposed API into the spec, so it's reviewed as a diff;
- adds `doctor`, `upgrade`, `sync [--check]`, `runs` and `prune`;
- makes `init`, `spec new` and `upgrade` never overwrite a person's files.

### Consequences

- Each command's `result` schema is written with the command's implementation; M0 fixes the envelope and lists the fields.
- The harness, not only a person, writes into a spec, during `propose`; the agent permission model notes it.
- The adapter boundary (T-0031) and the reusable workflow (T-0032) define what `init` writes for Vue and the CI stub.
